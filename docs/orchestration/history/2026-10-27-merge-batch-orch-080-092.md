## Risks and findings

- **The batch's one real hazard is the conflict `ort` could not separate.**
  On the first merge both sides had rewritten the *same adjacent pair* of
  board rows, ORCH-080 and ORCH-081, for unrelated reasons. `--theirs`
  would have reverted ORCH-080 to `owed`; `--ours` would have reverted PR
  #96's ORCH-081 row and lost D184's text from it. **Neither would have
  failed a gate.** Each side's own row was kept.
- **ORCH-107 gains a cheap first thing to check.** `./scripts/test.sh` run
  without `cargo build --workspace --all-targets` first makes the
  `real_herd` tests build the binaries they drive **inside their own
  `PATIENCE`**. ORCH-092's author saw 7, then 3, then 2 failing targets on
  identical code before working it out; across the four integrations of
  2026-10-27 this merger saw the same shape — **three targets red without
  the prebuild, two with it** — the target that drops out being
  `killed_hub` with a `real_herd/mod.rs:649` timeout. One observation
  repeated, not a proof, and it does not explain 21 failures at load 19;
  but it is one controlled pair of runs to settle, and it would shrink
  what is left. Now on ORCH-107's row as the first step of sizing it.
- **Correction 2026-10-27, written at batch 4's integration: the
  prebuild named in the bullet above is not the one that works, and
  ORCH-107 is now `done`.** `cargo build --workspace --all-targets`
  resolves a narrower feature set than `cargo test --workspace` does
  (dev-dependencies unify features across a workspace), so the tests'
  own `cargo build --offline -p herd-hub -p herd-runner -p herdctl`
  still compiled for **9.70 s** right after it, against **0.06 s**
  after the identical command. `scripts/test.sh` runs that identical
  command itself now. **The three-red-versus-two shape this bullet
  reports is therefore not explained by the prebuild**, and four runs
  at peak loads 9.6 to 18.2 produced zero `:649`/`:789` timeouts: the
  21 failures at load 19 stay **unexplained**. Nothing above is
  withdrawn; the reading of it is.
- **`#[ignore]`d means the suite is not a guard for the 308.** The table is
  asserted rather than printed, so it cannot drift silently — but nothing
  runs it unless someone passes `--ignored`. Worth knowing when ORCH-084 is
  taken, since 4 of the 308 are exactly its hazard.
