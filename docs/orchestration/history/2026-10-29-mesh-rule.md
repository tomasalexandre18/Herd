## Done

**The mesh-address rule exists, refuses by name, and binds nothing.**

`herd-runner/src/mesh.rs` (new) holds D11's first condition as a startup
rule. `--mesh-listen ADDR` is refused, naming the address and the reason,
for a **wildcard** (`0.0.0.0`, `::`), for an address of the
**default-route interface**, and for a **globally routable** address; it
is accepted for **loopback** and for a **private**, **CGNAT**
(`100.64/10`), **link-local** or **unique-local** address that is not on
the default-route interface. `--mesh-advertise ADDR` defaults to the
listen address, carries the same class rule, and is refused when given
with no `--mesh-listen`.

The rule is a pure function over one address and one reading of the host
(`HostRouting`), so every refusal is provable against a fixed host
fixture rather than against the machine the suite runs on. The reading of
the real host is separate: `/proc/net/route` and `/proc/net/ipv6_route`
for the interfaces carrying a default route, `getifaddrs` for which
interface holds which address.

**No socket is bound.** `mesh::MeshListener` is the only name
`TcpListener` has in the crate — the door the endpoint step walks through
— and nothing yet calls `bind`. The runtime guard asserts that the
process still holds no listener at all, as its own assertion, so the step
that binds has to come and change that line.

**The two invariant-3 guards are rewritten**
(`herd-runner/tests/confinement.rs`):

- `the_runner_binds_no_listening_socket` →
  `every_listening_socket_of_the_runner_is_its_mesh_address`. Old
  assertion: the set of the process's listening sockets is empty. New:
  every member of that set is the configured mesh address **and there is
  at most one** — plus, today, still empty. The runner under test is now
  started with `--mesh-listen 127.0.0.1:<port>`, so its joining the hub
  is also the acceptance proof for loopback. The walk is first made to
  find a socket this test bound on purpose, which the old version never
  did: a zero from a walk that can see nothing is not a result.
- `no_module_of_the_runner_can_bind_a_socket` keeps its name and changes
  its rule. Old: `TcpListener`, `UdpSocket`, `UnixListener`,
  `UnixDatagram` forbidden in every file of the crate. New: `TcpListener`
  permitted in **exactly one** file named in the test (`mesh.rs`) and
  asserted to really be named there; the other three still forbidden
  **everywhere, that file included**; every other file still forbidden
  all four. The matching is first made to fire on a line known to be bad
  and to stay silent on a comment.

`docs/runner-confinement.md` carries the rule, the two flags in the
configuration table, the two consequences below, where the rule refuses
rather than decides, and what the two guards now assert.

**Both consequences are written down as intended, in the module header
and in the document, and one of them is also a test**
(`a_single_nic_flat_lan_machine_has_no_permitted_address`): a single-NIC
flat-LAN machine has no permitted serving address and is therefore
outbound-only, which is what D10's listener-free path is for; and
loopback is permitted deliberately — the rule returns on it before the
routing is consulted, so no host shape can take it away and the
two-runner end-to-end can run on this workstation.

**The allowlist fallback was not needed.** The default-route reading is
decidable on Linux. Where it is *not* readable at all, the rule refuses
everything but loopback, naming the reason
(`Reason::RoutingUnreadable`) — which is the conservative half of the
fallback the brief offered, with no new configuration surface.

## Not done, and why

- **`mesh.rs` is declared from `herd-runner/src/main.rs`, not from
  `herd-runner/src/lib.rs`.** The brief forbids touching `lib.rs`
  (another agent held it), and only `lib.rs` can declare a library
  module. So the module compiles into the binary, its unit tests run in
  the bin test target, and three of its items are `#[cfg(test)]` and two
  carry `#[allow(dead_code)]` purely because a `pub` item of a *binary*
  is dead code when unused. **It belongs in the library** and the move is
  one line, `pub mod mesh;`; the endpoint step needs it there anyway.
- **The accepted `Mesh` is not carried into `Config`.** `Config` is in
  `lib.rs`. Startup prints the accepted address and the refusal is
  enforced; nothing downstream consumes it yet, which is correct for a
  step that binds nothing.
- **No endpoint, no capability check, no transfer.** S5 in the plan.
- **A scoped IPv6 link-local (`fe80::1%eth0`) is refused by name** rather
  than carried: `std` cannot parse the zone and the endpoint would need
  it. Refused with the reason and a suggestion, not silently dropped.

## Risks and findings

1. **A defect this step found in its own first version, and the reason
   `route_is_usable` exists.** This host's `/proc/net/ipv6_route` carries
   three `::/0` entries on `lo` with metric `ffffffff` and flags
   `00200200` — `RTF_REJECT | RTF_NONEXTHOP`, the unreachable default the
   kernel keeps when there is none. Read naively, `lo` becomes a
   "default-route interface". The rule now requires `RTF_UP` set and
   `RTF_REJECT` clear, and the fixture carries that exact line. Anyone
   writing a second reader of these files will hit it.
2. **A second defect, also found by its own test:** `::ffff:a.b.c.d` was
   classified correctly and then looked up in the interface list under
   the *mapped* spelling, found nothing, and **accepted this host's
   default-route address**. Normalisation now happens where the value is
   parsed, not where it is classified. `::ffff:` was a way round the rule
   for exactly as long as that one lookup was unnormalised.
3. **The `v1-sunlen` caution did not bite.** `nix develop` set `TMPDIR`
   to `/mnt/ssd_980/herd/claude/tmp/nix-shell.<id>` (about 40 bytes),
   which leaves `sockaddr_un`'s 108 within reach, and `confinement.rs`
   ran green on this base without `v1-sunlen`. It is still a latent
   failure on a longer `TMPDIR`, and `v1-sunlen` is still the fix.
4. **Where I think the rule may be wrong, which the brief asked for
   rather than agreement** — four places, in descending order of how much
   they bother me:
   - **"An address of the default-route interface" is a proxy, not the
     property.** The property invariant 3 cares about is *reachable from
     outside the operator's trust boundary*, and the default route is
     merely the usual shape of that. A machine behind CGNAT whose
     default route is a private `100.64/10` address is refused although
     nothing off its ISP can reach it; a machine whose mesh interface
     carries a more specific route to the world is accepted although
     something can. Both are conservative in the direction that matters
     (one over-refuses, and over-refusal costs an outbound-only runner,
     not a port), but the rule is not the property and someone will meet
     the first case.
   - **The rule is read once, at startup.** An interface that acquires
     the default route *after* the runner started is not re-judged. With
     no endpoint this is harmless; the endpoint step should decide
     whether to re-read, and my view is that it should refuse to serve
     rather than re-bind.
   - **`--mesh-advertise` is not checked against this host's own
     addresses.** I deliberately did not require it to be one of ours
     (a mesh may translate), so a typo advertises an address no peer can
     reach and the failure surfaces as a transfer that does not happen.
     The fetch path should name that state rather than wait on it.
   - **`getifaddrs` returning an empty list is read as "unreadable".** On
     Linux that is sound (`lo` always exists). If some container shape
     hides all addresses *and* exposes `/proc/net/route`, the result is
     a refusal, which is the safe direction but will read as a defect to
     whoever meets it.
5. **The guard's name is now slightly behind its rule.**
   `no_module_of_the_runner_can_bind_a_socket` permits one module to name
   the listener type. I kept the name because
   `docs/remediation/04b-integrity-and-containment.md`,
   `herd-hub/tests/fake_hub_flood.rs` and a 2026-10-24 handoff all cite
   it, and none of them is mine to edit. Its doc comment carries the new
   rule in full.
6. **The host's preflight refusal was lifted on a disclosed reading, not
   silently.** `./scripts/bench-preflight.sh` refused at 4 946 MiB of
   room under `memory.high` on `/chatons.slice` against its 8 192 MiB
   floor. `/sys/fs/cgroup/chatons.slice/memory.stat` read `anon
   738 893 824` (704 MiB) against `file 12 902 203 392` (12.0 GiB), with
   `memory.current` 13.2 GiB under a `memory.high` of 18 GiB and 23 116
   MiB available on the host — so the refusal was about reclaimable page
   cache. Re-run with `HERD_PREFLIGHT_MIN_CGROUP_ROOM_GIB=4`: `ok, safe
   to start`. Nothing was written under `/sys/fs/cgroup`.

### Drafted decision entry (D-NEXT; the merger allocates the number)

```markdown
## 2026-10-29 — D-NEXT The mesh-address rule, and both invariant-3 guards

**Context.** D11 (Alexa, 2026-10-12) amended invariant 3 so a runner may
listen on a private mesh interface to serve content to peers, under three
conditions, the first of which is a startup condition: a configuration
that would bind a public or default interface is refused at startup, the
way a bad data root is (E-45). Nothing enforced it, because nothing
listened; `herd-runner/tests/confinement.rs` instead asserted that the
runner binds nothing at all, in two guards whose own comments said they
would change when the fetch endpoint arrived.

**Choice.** `--mesh-listen ADDR` is refused at startup, naming the
address and the reason, for a wildcard (`0.0.0.0`, `::`), for an address
of the default-route interface, and for a globally routable address. It
is accepted for loopback and for a private, CGNAT (`100.64/10`),
link-local or unique-local address not on the default-route interface.
`--mesh-advertise` defaults to the listen address, carries the same class
rule and no routing check, and is refused with no `--mesh-listen`.
Where the host's routing cannot be read at all, everything but loopback
is refused rather than guessed at.

Both guards are replaced, and the second gets **stronger**:
`every_listening_socket_of_the_runner_is_its_mesh_address` asserts that
every listening socket of the real process is the configured mesh address
and that there is at most one, after first proving the walk can find a
socket planted on purpose; `no_module_of_the_runner_can_bind_a_socket`
permits `TcpListener` in exactly one named module — `herd-runner/src/mesh.rs`,
which owns `mesh::MeshListener` — and keeps `UdpSocket`, `UnixListener`
and `UnixDatagram` forbidden everywhere, that module included. One named
module is a tighter statement than "nowhere" plus an exception nobody
wrote down.

**Two consequences, accepted rather than worked around.** A single-NIC
flat-LAN machine has no permitted serving address and is therefore
outbound-only — the cost of *"never behind a port forwarded on someone's
box"*, and why D10 keeps a path that needs no listener. And loopback is
permitted deliberately: it is reachable from nothing off the machine, and
the two-runner end-to-end that makes the pack half done (invariant 5)
runs two runners on one workstation.

**Alternative rejected.** An explicit allowlist in the configuration plus
a refusal when nothing is declared. Strictly more conservative, and the
fallback if the default-route reading had proved undecidable — it did
not, on Linux, so the allowlist would have been configuration surface
that bought nothing (invariant 1). The conservative half is kept where it
is needed: an unreadable host refuses everything but loopback.

**Not a weakening of invariant 3, and no Alexa question.** The invariant
as written already permits exactly this, D11 approved it on 2026-10-12,
and `docs/joining.md` states the property publicly (D209).

**Evidence.** D10, D11, D200, D209; invariant 3; `herd-runner/src/mesh.rs`;
`herd-runner/tests/confinement.rs`; `docs/runner-confinement.md`.
```
