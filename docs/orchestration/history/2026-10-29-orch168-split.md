- **collected files** — `files/`, `files.part/`, `files.gone/`: the bytes the
  output budget governs (D148, D152), with a file count at every depth.
- **the records** — `job.json`, `events.jsonl`, `log.seq`, and any
  subdirectory a later milestone adds, with a record count.
- **the logs** — the `log` file, with a log count, and the population nothing
  on the hub bounds.

**Four things it settles, each with a test.**

1. **The record population is measured positively, not by subtraction.** The
   walk reads each job directory's own entries and sorts them into the three
   populations; it never computes `record = total − outputs`. So a log that
   cannot be measured leaves the log's place empty instead of silently moving
   its bytes into the record's.
2. **A missing or unreadable log is UNKNOWN and named, never nought.**
   `LogWeight::Unknown(why)` is counted in its own line, named with its id and
   its reason, and contributes nothing to `log_bytes`;
   `Weighed::measured_bytes()`
   is `None` for that record, and the class's `measured_bytes()` is printed
   immediately under the unknown count so that a floor is never read as a
   total.
3. **A log nothing ever wrote is a measurement, not a gap.** The hub writes
   `log.seq` the moment a job is assigned and creates `log` lazily on the
   first byte, so a job cancelled while queued genuinely has no log. That case
   is `LogWeight::NeverWritten` and gets its own `no log ever written` line;
   a `log` missing from **beside a `log.seq`** is the unknown case. Every
   record on a side is in exactly one of the three — `logs + logs_unknown +
   without_log == records`, asserted in two tests.
4. **A record naming no collected file still weighs.** `without_collected_file`
   is counted and printed (`naming no file`), because 41 % of the first
   consumer's records name no file and a figure that could only see `files/`
   would read every one of them as nought.

**It is still a preview.** No lock, no write, no deletion path, no flag that
could be given one, no new subcommand and no new flag of any kind: one walk,
more answers. `RetentionPreview::read` opens files read-only and
`fs::metadata`; `weigh` and `files_in` only `read_dir` and `metadata`. Six
tests assert the root is byte-identical before and after, by a full
path, length **and modification time** listing — a length alone would pass a
write that replaced a byte without changing the count, and reading never
moves an `mtime` — one of them with the `flock(2)` on `hub.lock` held by
somebody else and one against a root a `JobDirStore` still has open.

**Not touched:** `herd-hub/src/store.rs`, `report.rs`, `main.rs`, `lib.rs`,
`herd-proto`, `herdctl`. No version number moved (`RECORD_VERSION`,

**The fixture is arithmetic a reader can check.** Every `job.json` is padded

`metadata().len()`. The hand arithmetic of all eight per-class figures and

## Risks and findings

1. **`log` and `log.seq` are written again in `retention.rs`, not imported.**
   They are private `const`s in `store.rs`, which another task owns
   exclusively, so widening them was not available. The duplication is held by
   a test rather than a comment:
   `the_preview_reads_what_the_store_itself_wrote`
   now appends a real log line through the store's own writer
   (`JobStore::append_log`) and asserts the measured figure and that
   `record_bytes == job.json + events.jsonl + log.seq` off the real listing. A
   rename in `store.rs` therefore fails there instead of printing nought for
   every log on an operator's root. **Finding for whoever next owns
   `store.rs`:** make `LOG_FILE` and `LOG_SEQ_FILE` `pub(crate)` and delete
   the copies. One line each, and it is outside this brief's paths.
2. **A refinement of the brief, stated rather than hidden.** The brief said
   "a missing or unreadable log is counted as unknown and named". The hub
   creates `log` lazily on the first byte, so on a real root a great many
   records have no log *because none was ever written* — the first consumer's
   1 377 file-less records will include many of those. Reporting all of them
   as unknown would have drowned the figure the relay is meant to read. So
   absence is split in two by the hub's **own** witness: no `log` beside a
   `log.seq` is UNKNOWN and named; no `log` and no `log.seq` is `no log ever
   written`, a measurement. Both are printed, both are counted, and the three
   counts add up to the record count, so nothing is hidden either way. If the
   orchestrator wants the brief's literal reading instead, it is a two-line
   change in `weigh`.
3. **`measured in all` is a floor, not a total, whenever a log is unknown.**
   The output says so by printing the unknown count immediately above it, and
   `Weighed::measured_bytes()` returns `None` per record. Anyone quoting the
   root figure from the consumer's run must quote the unknown count with it.
4. **The collected count is a count of *names*, not of inodes.** It is right
   today and will over-count once S4 shares blobs by hard link — the same
   direction as B1's byte figure, and the same owner (S5).
5. **The output is longer**: the per-class block grew from 9 lines to 17 a
   side. On the consumer's four classes that is about 70 lines more. Judged
   worth it — the figure the whole retention group gets sized against is in
   those lines — but it is a change an operator will notice.
6. **`Seen` changed shape**: `bytes`/`output_bytes`/`record_bytes()` became
   one `weighed: Weighed`, and `ClassPreview`'s `expired_bytes`,
   `expired_output_bytes`, `inside`, `inside_bytes` became `past: Weight` and
   `inside: Weight`. `lib.rs`'s re-export list is unchanged and still valid;
   `main.rs` only calls `read`, `Display` and `verdict.refusal()`. No other
   crate reads these types — checked by grep across the workspace.
