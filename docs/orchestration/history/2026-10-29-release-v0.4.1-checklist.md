## 2. The three numbers, read from the source as `release.yml` reads them

A patch release for this defect **must not move one of them**: a build at
a higher layout or record version refuses to open, or misreads, the state
root the consumer already has — which is the opposite of the point. All
three are unmoved.

| Constant | File:line | At `v0.4.0` | On this branch |
|---|---|---|---|
| `PROTOCOL_VERSION` | `herd-proto/src/lib.rs:114` | 2 | **2** |
| `RECORD_VERSION` | `herd-hub/src/job.rs:52` | 1 | **1** |
| `LAYOUT_VERSION` | `herd-hub/src/store.rs:59` | 1 | **1** |

Read verbatim off this branch:

```
herd-proto/src/lib.rs:114:pub const PROTOCOL_VERSION: u32 = 2;
herd-hub/src/job.rs:52:pub const RECORD_VERSION: u32 = 1;
herd-hub/src/store.rs:59:pub const LAYOUT_VERSION: u32 = 1;
```

The first two are what `release.yml`'s *the protocol and the record
version, from the source* step extracts with `sed` and refuses if empty,
non-numeric or doubly declared (**D168**). Both declarations are the
single `pub const …: u32 = N;` form that step requires. `LAYOUT_VERSION`
is not read by the workflow; it is checked here because board row
ORCH-156 asks a release to state it.

Compatibility is not something this project preserves any more. The
reason these must not move is narrower and specific to this release:
**this build has to open their existing root.**

## 7. The release body, and the known gap in how it reaches the page

**`release.yml` never reads a prepared file.** The published body is
`cat body-dev.md body-head.md body-image.md body-tail.md`, where
`body-dev.md` is empty outside the dev lane, `body-head.md` and
`body-image.md` are generated by the workflow itself, and
`body-tail.md` is a link line plus `cat deploy/release-notice.md`
(`.github/workflows/release.yml`, the *write the release body* and
*attach the archive* steps). There is no input, no file path and no
fourth piece.

So the human half of this release is written here —
`docs/orchestration/history/2026-10-29-release-v0.4.1-body.md` — **for
the record, and it will not reach the page by itself.** Whoever pushes
the tag pastes it. That is **D210**'s interim rule, and it is exactly how
v0.4.0 went out at 13:50:10Z missing both of its operator cautions.
**Closing the gap is ORCH-162's task and is deliberately not designed
around here:** the drafted shape is a per-release
`deploy/release-notes/<version>.md` that `release.yml` `cat`s as a fourth
piece, with `check-docs.sh` asserting one exists for the workspace
version. Inventing a different shape on this branch would collide with
it.

The body therefore carries, besides the fix: the 5 s stop grace, and
ORCH-161's order of operations (`herd-hub report` before a hub start on
an old root). Every release body owes those two until ORCH-106 lands.

## 10. The tag command, which was not run

`herd-release` prepares and never publishes (`CLAUDE.md`;
`.claude/agents/herd-release.md`; `release-guard.sh` enforces the shell
part). **No tag was created, no tag was pushed, no release was created
or edited, no workflow was dispatched, nothing was deployed.** The
branch `cut-v0.4.1` is pushed and nothing else.

Landing the branch is `herd-merger`'s, one landing per batch. Landing a
version branch is **not** publishing its release: they stay separate
acts. After the landing, on the landed sha, the tag is:

```sh
git tag -a v0.4.1 -m "v0.4.1: a runner no longer deletes the spools it recovers" <landed sha>
git push origin v0.4.1
```

Then the human half of the body has to be pasted onto the published page
above the generated head, from
`docs/orchestration/history/2026-10-29-release-v0.4.1-body.md`, because
`release.yml` will not put it there.

**That paste is Alexa's own act and no agent's**, and that is not a
courtesy — it is **D210**, and it is what the permission system
enforces: the auto-mode classifier refused `herd-step` the one
`gh release edit --notes-file …` at v0.4.0, and
`.claude/hooks/orchestrator-guard.sh` refused the orchestrator the same
command. Both refusals were correct, D210 says neither wall is to be
weakened, and no agent retries it. **Alexa's word is no longer needed
for the tag** (2026-10-29: *"pour le tag on s'en fou, tout va être
reset"*), which changes who may tag; it does not change who may write to
a public page. So the order a release brief carries is: land, tag, and
the paste **in that same order**, so the page is never public and
incomplete in between. ORCH-162 is what retires this.
