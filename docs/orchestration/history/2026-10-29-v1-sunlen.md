## Risks and findings

1. **The fixture now writes outside the worktree and outside `TMPDIR`**:
   one directory named `herd-planted-socket-<pid>-<n>` under
   `XDG_RUNTIME_DIR` or `/tmp`, removed on drop. It was already writing
   outside the worktree (under `TMPDIR`), so this is a change of place
   and not of kind; a `SIGKILL`ed test leaves an empty directory behind
   there, as it already did under `TMPDIR`.
2. **`/tmp` is shared.** The name carries the pid and a per-process
   counter, so two agents cannot collide, but `/tmp` is world-writable:
   a hostile local user could pre-create the directory. That is true of
   every `/tmp` user on the host and this is a test fixture, so it is
   recorded rather than defended against.
3. **`LONGEST_BOUND_NAME = 24` is a budget, not a measurement.** The only
   name bound today is `planted.sock` (12 bytes). A future 25-byte name
   would pass `ShortDir`'s check and then be caught by the assertion at
   the bind site, which is the right order: a named failure with a
   figure, never `ENAMETOOLONG`.
4. **ORCH-139's title is still half the story** and should be corrected
   when the row is closed: the trigger is the **total length of the bound
   path**. The row's own amendment says so; the title does not.
5. Nothing in the gates covers the long-`TMPDIR` case on its own. The
   gate runs the suite under whatever `TMPDIR` the caller exported, so
   this fix removes the failure but no gate step asserts it is gone. The
   assertion inside the fixture is what holds it, and it is in the suite.
6. **A second red, and it is not this branch's**, found by the first gate
   run and worth a row of its own: the library test

   ```
   reclaim::tests::the_reaper_kills_a_job_whose_runner_is_gone_and_spares_one_whose_runner_is_not
   ```

   panicked at `herd-runner/src/reclaim.rs:685` with `the orphan 4041154
   was not found among []`. It plants a marked child and then expects
   `orphaned_job_processes()` to see it; the list came back **empty**, so
   the scan ran before the child had its marker, or the `/proc` walk
   missed it. The host was loaded at the time — the flood benches in the
   same run read **12.56** — and `one_reaper_at_a_time()` already guards
   the one race the test's own comment knows about, so this is a
   *different* one. One sample, on an integration-test-only branch, which
   makes it a lead and not a diagnosis: it needs N runs a side before
   anyone touches `reclaim.rs`. It is in nobody's expected-skip list
   because it is a failure and not a skip.
