## The design choice, and why

**A document in the state root, not a `FromHub` frame.** The plan's own
reason for a document — a new frame to a requester is a breaking change
with no second chance — is void: Alexa's direction of 2026-10-29 is that
compatibility is not preserved, the consumer resets entirely at v1.0.0,
so the protocol may move whenever it is useful. The choice was therefore
made again, on the merits, and three things decided it.

1. **A reader takes no lock and writes nothing.** `Status::read` is one
   read-only open of one file: no `flock` on `hub.lock`, no store
   `Mutex<Live>`, no dispatch pass held up, no frame to serialise, no
   connection to authenticate. A frame cannot promise that — answering
   one takes the peers lock on the serving path — and this is a question
   dashboards ask in loops, precisely when the hub is busiest.
2. **A hub that has stopped still answers.** The last document stays on
   the volume with the moment it was published and a `stopping` flag
   saying whether the hub was on its way out when it wrote it. *What was
   the fleet doing when it died* is the first question after an outage,
   and it is the one question a live query can never answer.
3. **It is where the operator already looks.** Herd is shipped, not
   operated (D161, invariant 9): the consumer reads records off that
   volume today (E-53). `herd-hub report` and
   `herd-hub retention-preview` are the precedent — answer a question
   about the state root without touching the hub (ORCH-125) — and
   `herd-hub status` joins them, needing no port, no token, no image and
   no `herdctl` build.

What a frame would have bought is a live answer instead of the last
published one. That gap is bounded by `status::AT_MOST_EVERY` (250 ms)
and is not a refresh interval: a quiet hub publishes nothing at all, and
a change is published as soon as the writer can build it. The cost is
named rather than hidden — the document carries `as_of`, and the screen
prints how long ago that was.

**No version number moved.** `PROTOCOL_VERSION` stays 2,
`RECORD_VERSION` 1, `LAYOUT_VERSION` 1. A new, purely additive file
under D8's discipline needs none of them: an older Herd reading that
root ignores it, there is nothing to migrate, and no peer or record
shape changed. `STATUS_VERSION` is 1 and is the document's own, separate
on purpose — a renderer must be able to learn that *this* shape moved
without being told the whole volume is unreadable (Q7).

## Done

- `herd-hub/src/status.rs`, new: `STATUS_VERSION`, `STATUS_FILE`
  (`status.json`), `AT_MOST_EVERY`, the document's types, `Status::read`
  (no lock, no write, version refused by name with both figures),
  `Status::same_but_for_the_clock`, and `Display` — the one text screen
  E-35 asks for, rendered from the document and from nothing else.
- What it carries: the hub's build, state-root identity, protocol and
  record versions, the health cadence and the lost-after threshold, the
  output budget, and whether it is stopping; every connected runner with
  its build, instance, switch and reason, drain flag, preference, the
  moment it was last heard from, how many reports that is, its load, what
  it lends (memory, floor, threads, tmpfs, jobs-at-once, every capability
  with kind, slots, origins and any suspension reason) and what it says
  it holds; every runner approved here and **away**; every job out on a
  machine with its state, runner, attempt, level, labels, start and its
  E-36 placement line; every queued job with its level, labels,
  submission moment, attempts so far and **what it is waiting for**.
- Published **on change and on nothing else**: the writer sleeps on a
  bell rung by `State::with_peers`, the one door to every live fact about
  the fleet. A document identical to the last is not written, one
  `Notify` permit coalesces a burst into one more build, and
  `AT_MOST_EVERY` bounds the worst-case cost at four queue walks a
  second. A last publication is written straight on the stop path, so it
  does not race the task's abort.
- `last_health_at` is a new field on `ConnectedRunner`: the wall-clock
  moment beside the existing `Instant`, taken once where a report lands.
  An instant and not an age, so the document is not stale when the file
  closes; taken once, so it changes only when a runner speaks, which is
  what keeps the document off a timer. Nothing judges a timeout on it.
- `Hub::publishing_status_to(root)`, which the binary always calls; a hub
  nobody tells writes nothing (the in-process hub most tests build).
- `herd-hub status [STATE_DIR]`, a third read-only subcommand beside
  `report` and `retention-preview`, placed before the lock and the
  sweep. It prints the screen plus one line saying, against its own
  clock, how old what it printed is. It exits 1 naming `status.json` when
  no hub has published in that root: an unanswered question must not exit
  0, and an absent document is not an empty fleet.
- **An unknown is never a zero.** Every figure the hub may not know is an
  `Option` left off the JSON entirely and printed `unknown` on the
  screen: an unreadable load, an unexposed tmpfs capacity, a runner that
  announced no build, a `shared` capability's absent holder limit, and a
  queued job the hub has not yet computed a reason for — which the screen
  says as `no reason recorded yet`, not as a blank.
- Tests: nine unit tests in `status.rs`; three end-to-end tests in
  `herd-hub/tests/status.rs` with a real hub, a real runner and real
  jobs. They prove the fleet's own figures reach the document, a real job
  is named where it runs with its E-36 line, a real queued job carries
  the record's reason **word for word**, a quiet hub does not rewrite the
  file over four seconds while it is read a thousand times, a change
  lands inside two, and `herd-hub status` answers in under two seconds
  against a root whose hub holds the lock with a job in flight.
- `docs/architecture.md`: the "not built" row that said M13's status
  document does not exist now says what does exist and what of M13 still
  does not.

## Not done, and why

- **E-37, the events** (the other must of M13). Out of this brief, which
  is E-35 and E-40.
- **Use against the output budget** — D152's "what M12 still owes" and
  one line of `docs/handover.md`'s replacement table. The budget is on
  the document; the use against it is a walk of `jobs/*/files`, and
  putting it here would make every publication a walk of the volume.
  `herd-hub report` already answers it on demand. Named in the module's
  own docs as a deliberate absence, not an oversight.
- **Evictions so far**, from the same table. The hub keeps no counter of
  them (D79's rule: nothing is counted that can be derived), so there is
  no figure to carry and none was invented.
- **A renderer or a schema file.** M13's *done when* asks for an e2e
  snapshot validating against a schema and driving a fixture renderer.
  What exists is the typed document, which `Status::read` validates by
  deserialising and by version, and `Display` as the renderer with no
  other source. A separate JSON Schema was not written: there is no
  consumer for one yet and it would be a second definition of the shape.
- **`docs/coverage.md` and `docs/status.md` are untouched**, and so is
  `docs/orchestration/board.md`. Proposals below; the merger records.
- **`docs/decisions.md` is untouched** — the brief asked for no entry.
  One is arguably owed for the document-over-frame choice; the merger
  allocates the number if the orchestrator wants it.

## Risks and findings

1. **The red step 6 is the host, and it is reproducible as such.** Every
   failure in the three gate runs is a real-binary test whose runner
   refused to start, in the runner's own words:
   *"announcing 661 MiB of memory rather than 31.1 GiB, because
   /proc/self/cgroup is enclosed by memory.high 18 GiB on
   /chatons.slice, which already holds 17.3 GiB"*, then
   *"--host-memory-floor is 1024 MiB and this host lends 661 MiB, so
   nothing could ever be admitted here"*. The slice's room was read at
   3 MiB, 661 MiB and 772 MiB during those runs, against 4 857 MiB a
   minute before one of them. The failing files differ run to run
   (`approval.rs`, `slots.rs`, `owner_control.rs`) and are files this
   branch does not touch; `real_herd::a_lend_this_host_can_really_make`
   names this exact hazard and says *"run the suite outside the slice,
   or raise the slice's ceiling"*. Three sibling tasks were building on
   this host throughout, and page cache counts in `memory.current`.
   **Not fixed here**: raising the slice is a change on the host, and
   nothing in Herd may make it (D161, invariant 9, shared-host rules).
2. **One harness change this branch forces, and its compensation.**
   `Herd::state_bytes` now leaves `status.json` out of its snapshot. It
   has to: a serving hub republishes the document on every health report
   — five times a second in these tests — so
   `until_the_state_root_is_quiet` would never return and E-07's
   before/after comparison would be measuring the health cadence. It is
   an **exclusion and not an exemption**: the dry-run test in
   `owner_control.rs` now asserts that a `would-run` leaves the
   document's runners, its running jobs and its queue exactly as they
   were, which is E-07's claim about this file with the health age taken
   out of it. No assertion was weakened to make anything green; one was
   added. Flagged because editing another test's harness is the kind of
   change that must be seen, not assumed.
3. **A consequence worth stating plainly: the state root is never
   byte-quiet while a runner is connected.** That is what E-40 asks for
   — an age that moves is the only way to tell a runner that has stopped
   talking from one with nothing to do — but it is new, and any future
   test or tool that assumes a quiescent volume now has to know about
   this one file.
4. **`AT_MOST_EVERY` is a chosen figure, not a measured one.** 250 ms,
   picked as the longest delay nobody reading a screen would notice. The
   cost it bounds — four `unfinished_jobs()` walks a second in the worst
   case, on top of the hub's own dispatch passes — is arithmetic, not a
   reading: no bench was written for it. If it ever matters, the bench to
   write is a publication-rate cost bench beside `walk_cost.rs`.
5. **The "no clock" proof is in two halves, and each is only decisive
   beside the other.** Four seconds of quiet with the file byte- and
   mtime-identical excludes any writer on a period at or under four
   seconds; a change published inside two seconds, three more times in a
   row, excludes a longer one. Said here because neither half alone
   proves it, and a reader of the test should know which is which.
6. **`herd_hub::Status::read` refuses a document of another
   `STATUS_VERSION`** rather than reading the fields that happen to
   match, following D73. That means a `herd-hub status` from one build
   against a root served by another is a refusal naming both figures —
   correct, and worth knowing before somebody meets it.
7. **One flake seen and not caused here.** The first gate run also hit
   `Address already in use (os error 98)` on an ephemeral port in
   `approval.rs` — the hazard `Herd::approve` documents at length. It did
   not recur.
