## Risks and findings

1. **E-23's term is inert in a running fleet today, and will be until
   something registers a pack.** `ToHub::RegisterPack` is constructed in
   **0** places under `herd-runner/src`; the same grep finds **18**
   occurrences across the tree, in `herd-proto`, `herd-hub/src/server.rs`,
   `herd-hub/src/registry.rs` and two `pack_frames.rs` test files, so the
   zero is a measurement and not a silent detector. `ToHub::PacksHeld` is
   constructed in **10** places under `herd-runner/src`, so **holdings do
   arrive** and `holders_of` can answer; what nothing fills is the
   registry, so `pack_for(commit, key)` is `None` for every key in
   production and `holders_of_what_it_needs` returns an empty map. The
   term is therefore correct, tested, and unobservable outside tests until
   M11's layout step constructs that frame. Drafted as a board row below.
2. **The locality figure is a count of *manifests*, not of bytes held.**
   A runner announces the packs it holds whole (`holds_whole`), so the
   term says "it has this many of the manifests this job needs" and not
   "it would fetch this many bytes fewer". On a job needing two packs of
   very different sizes, holding the small one outranks nothing and
   holding the large one outranks nothing differently. A byte-weighted
   term is exactly the weight invariant 1 refuses, so this is a limit
   recorded, not a defect to fix.
3. **One cost, bounded and named:** `holders_of_what_it_needs` is called
   once per queued job per dispatch pass. For a job with no `needs` it
   returns before taking a lock or asking for a registry, so today's
   queues pay nothing measurable; for a job with `needs` it takes the
   registry's mutex once per key and reads no file. Nothing here was
   timed — it is derived from the code path, and said as such.
4. **Two branches in flight touch the neighbourhood and this one does not
   conflict with either by inspection:** M12's R1 (`store.rs`, `job.rs`,
   `main.rs`, a third field on `Budget`) and P2a (`herd-runner/src/lib.rs`).
   This branch changes `herd-hub/src/matcher.rs` and
   `herd-hub/src/server.rs` only. The `server.rs` overlap with R1 is
   nothing by line (R1 owns `main.rs`/`job.rs`/`store.rs`), but **P2b and
   P6 both own `server.rs`** by the plan and must not land in the same
   batch without a look.
5. **`clippy --workspace --all-targets` was run after the last test was
   written**, which is the trap the brief names: both new test bodies
   construct `Placing` and `Registration`, and a branch that widened
   either after `a8cf397` would break here with a compile error rather
   than a silent answer.

```markdown
## 2026-10-30 — D-NEXT Locality is a third term, not a second mechanism

E-23 asks the hub to prefer a runner that already holds what a job
needs. **Decided:** one further term on the order
`matcher::place` already had, between the declared `preference` and the
name — how many of the packs this job's `needs` resolve to the machine
already holds, descending. Preference stays the first word, so a higher
declared `preference` still wins over a holder and `best` is computed
without consulting a holding at all; the name stays the last word, so the
same fleet still makes the same choice twice.

**What was refused in taking it.** A weight over bytes, a per-key or
per-label rule, an operator setting, and a second sort pass were each
available and each is the generic-CI surface invariant 1 refuses,
arriving as an optimisation. The term is an integer compared against an
integer, with no configuration and no protocol change: both frames it
reads — `ToHub::PacksHeld` and the registration — already exist at
`PROTOCOL_VERSION` 3.

**A requester never names a machine** (invariant 6). The job declares the
keys it consumes; who holds the pack a key resolves to is what runners
announced to this hub, and turning an announced holding into a preference
is the hub's own act. The matcher is handed the answer as data —
`Placing::holds_what_it_needs` — for the reason it is handed a parent
(E-10): it is a pure function of a record and a fleet, and a holding it
read for itself would make it a function of a disk.

**The clause this decision really rests on is the one that asserts
nothing changed.** Every job Herd runs today has no `needs` at all —
nothing fills the field unless a declaration asks — so this is the one
change in the matcher that could silently re-order every placement in
the fleet. Six placements over a three-seat fleet, every job with an
empty `needs`, are frozen byte for byte against a literal captured on
`a8cf397` with `place` unmodified, and the expectation was written and
seen green **before** the term was. The detector was proved on a
known-bad instance — reversing the name tie-break turns it red — so its
silence is evidence. `locality_sentence` returns nothing at all for such
a job rather than a shortened clause, which is why the sentence an
operator reads is the same bytes and not merely the same meaning.

**And it is inert until something registers a pack.**
`ToHub::RegisterPack` is constructed in zero places under
`herd-runner/src` (18 occurrences elsewhere in the tree, so the zero is
measured), so `pack_for` answers `None` for every key in production and
the term never fires outside its tests. That is M11's layout step to
close, and E-23's end-to-end waits on it.
```
