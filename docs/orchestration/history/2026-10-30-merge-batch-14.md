## Risks and findings

0. **A disjoint file set is not an additive merge, and this is the
   finding of the landing.** The brief said this branch *should* merge as
   additive and asked for the claim to be verified rather than trusted.
   Verified, and both halves of the answer matter: at the **file** level
   it was exactly as predicted — two new files, disjoint sets, no textual
   conflict, git asked nothing — and the integration tip still **did not
   compile**, because `main` had added a field to a struct the new test
   constructs. The two properties are independent, and no `git` output
   distinguishes them: `Merge made by the 'ort' strategy` is not a
   statement about whether the result builds. **What caught it was the
   merger gating its own integration tip**, which is the whole reason
   step 7 exists and the reason an agent's own green gate is never the
   landing's — `runner-silence`'s gate was genuinely green on its own
   base, and the author did nothing wrong; `main` moved under it. The
   generalisable rule for the next batch: a branch based on anything
   older than `origin/main` that **constructs a type** owned by another
   crate can break without a conflict marker, and only a compile says so.
   Two landings in a row have now been bitten by an ancestry-shaped
   assumption, by two different mechanisms.
1. **The drafted keepalive row would have failed the docs gate as
   written, and the brief's warning was exactly right.** It carried three
   escaped pipes — two in the `Ping`, `Pong`, `Frame` match arms and one
   in a `grep` alternation. `check-docs.sh` counts columns with
   `awk -F'|'`, which splits on the literal character and does not
   honour a backslash, so the row arrived at **NF=13** against the
   required 10. Measured before insertion, not after a red gate. Both
   phrases were **reworded rather than escaped**, which is the only thing
   that works: the arms became *the three arms that `continue` on
   `Ping`, `Pong` and `Frame`*, and the alternation became *a search for
   `Ping` and for `Pong`*. The reworded row asserts to NF=10.
2. **The orchestrator's refuted premise is confirmed refuted, and the
   refutation has a consequence this landing changes.** The branch was
   briefed that `gate.sh` names an `#[ignore]`d test as a compile-time
   skip; that is **true of `main`** — `scripts/expected-skips/ignored.txt`
   is there with 38 names, from `orch202-ignored-skips` via batch 13 —
   and **false of the branch's base**, which does not have that branch in
   its ancestry. The author was right to refute it. **What follows for
   this landing:** the branch's argument for no `#[ignore]`d twin leaned
   partly on that absent mechanism, and the integration tree **has** the
   mechanism. It does not reopen the choice, because `silent_hub.rs`
   carries no `#[ignore]` attribute at all — the two matches for the
   string in that file are at lines 71 and 76 and are both `//!` doc
   comments explaining why no twin was written. So `ignored.txt` needs no
   new line, the gate's refusal of a reasonless `#[ignore]` is not in
   play, and the 38 names are unchanged. Checked, because an `#[ignore]`
   arriving on a tree that now compares them by name would have been a
   red gate with a confusing message.
3. **The branch's file is 539 lines, not the 487 the brief gave.** A
   small thing, reported because a figure in a brief becomes an
   acceptance criterion. The handoff is 441 lines, which the brief gave
   correctly. Nothing rests on either number.
4. **The placement argument was verified, not accepted.**
   `no_module_of_the_runner_can_bind_a_socket` walks
   `herd_runner::testing::source_files()`, which is scoped to the
   `herd-runner` crate, and permits `TcpListener` in exactly one named
   module. A test in `herd-hub/tests/` is outside that walk, so the file
   is in the right crate for the right reason and invariant 3 is not
   bent. `silent_hub.rs` does bind a listener, at line 169.
5. **The keepalive hazard is real and is the most important thing in this
   batch**, and it is not what the batch tested. `next_message` restarts
   its `tokio::time::timeout` on every frame it loops past, so a ping
   every 30 s from either peer — **or from a reverse proxy generating its
   own, and `deploy/reverse-proxy/` ships two configs** — resets the
