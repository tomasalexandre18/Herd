**ORCH-251 carries the finding this batch is most worth remembering.**
`DataRoot::open` canonicalises what it validates (`root.rs:140`), so
every store inside a running runner is opened under a canonical path,
while `main.rs` still holds the path the operator typed. A budget keyed
on that literal string would have registered against a spelling
nothing else ever reads, and `budget()` would have answered `None` for
a store that was given one. P2a reports exactly that triple, so it
would have published *no budget, 0 bytes* for a runner holding
gigabytes — wrong in the one direction an operator acts on, and
visible only on a machine nobody here may log into (`D161`), so no
gate here would ever have shown it. **Every one of P1's gates was
green before it was found, and it was found by reading.** P1 closed it
with `keyed()` and holds it with
`two_spellings_of_one_data_root_are_one_store`.

end*; P1 gives it a budget at the runner end. It now says there is no
retention or sweep, that the runner takes a budget and evicts nothing,
and that the deployed unit names none. The file was **at its 90-line
