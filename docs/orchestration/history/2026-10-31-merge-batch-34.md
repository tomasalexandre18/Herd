## What changed and why

**No milestone moves and no `E-nn` expectation comes with this batch.**
It is a method batch: prose, one guard, and one doc comment. What `main`
can do that it could not before is refuse a landing record that drops
its predecessor's post-push `ci.yml` run — a prohibition that until now
was held by memory alone, and that broke at batch 32.

Three things land together:

1. **A guard where there was none.** `scripts/check-orchestration.sh`
   gains a case group, *a landing records its predecessor's post-push
   run* (11 cases), which reads the newest `*-merge-*.md` under
   `docs/orchestration/history/` and refuses a record that does not name
   the previous landing's batch together with a run id and a verdict for
   it **inside one paragraph**. It runs at **step 2 of `gate.sh`**, so a
   record that drops the figure reddens its own landing before any Rust
   step. It has no network: it checks that somebody went and looked, not
   that what they wrote is true.
2. **The method's own documents stop contradicting that guard.**
   `workflow.md`, `templates/landing.md` and `.claude/agents/herd-merger.md`
   said the predecessor's run is recorded in the next landing's **board
   edit**, not in its **record** — so a merger following them to the
   letter went red at its own gate. All three now put the id and its
   verdict in the record, in one paragraph with the batch they belong
   to, and keep the board edit as practice.
3. **Two hand-maintained totals leave the tree, and the rule behind
   them is written down.** `scripts/report-skips.sh` names
   `scripts/expected-skips/ci.txt` instead of carrying *"15 skips when
   green"* — a figure whose own qualifier was the false part, taken from
   a red, incomplete run (**D179**) — and `herd-runner/src/cgroup.rs`
   names that list instead of *"the thirteen standing skips"*. The rule
   is **D288**, in `scripts/expected-skips/README.md`.
