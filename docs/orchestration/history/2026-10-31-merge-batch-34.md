## What changed and why

**No milestone moves and no `E-nn` expectation comes with this batch.**
It is a method batch: prose, one guard, and one doc comment in a test.
What `main` can do that it could not before is refuse a landing record
that drops its predecessor's post-push `ci.yml` run — a prohibition
that until now was held by memory alone, and that broke at batch 32.

Four things land together, and the last two exist only because the
first two were measured after they were written:

1. **A guard where there was none.** `scripts/check-orchestration.sh`
   gains a case group, *a landing records its predecessor's post-push
   run*, which reads the newest `*-merge-*.md` under
   `docs/orchestration/history/` and refuses a record that does not
   name the previous landing's batch together with a run id and a
   verdict for it. It runs at **step 2 of `gate.sh`**, so a record that
   drops the figure reddens its own landing before any Rust step. It
   has no network: it checks that somebody went and looked, not that
   what they wrote is true.
2. **The method's own documents stop contradicting that guard.**
   `workflow.md`, `templates/landing.md` and
   `.claude/agents/herd-merger.md` said the predecessor's run is
   recorded in the next landing's **board edit**, not in its
   **record** — so a merger following them to the letter went red at
   its own gate. All three now put the id and its verdict in the
   record, and keep the board edit as practice.
3. **The guard's own oracle was replaceable by accident, and was
   replaced.** `herd-reviewer` extracted the first oracle's `awk` and
   measured **three ways to pass it with nothing recorded**: a table
   whose predecessor row said *not read yet*, the word *successful*
   beside a byte count, and a record merely **quoting one of the
   check's own case names**. The oracle is now **one labelled field**,
   `- **Previous run:**`, anchored, placeholder-refused and
   shape-checked — which is **D290**. In the same branch, a defect
   that let the host's **load** decide 45 of this script's cases was
   fixed (**ORCH-336**): `gate_run` built every child with `env -i` and
   an assignment list that dropped `HERD_GATE_LOAD_MAX`, so the
   script's own self-tests went red above load 24 and reported it as a
   defect in the tree.
4. **The merger's own instructions learned the new form**, so that the
   next merger is not trapped by the document that tells it what to do
   (**ORCH-337**). The gate cannot check this: it reads records, not
   agent files, and a case that read prose is the thing D290 retires.

**Two hand-maintained totals also leave the tree** and the rule behind
them is written down as **D288**, in `scripts/expected-skips/README.md`:
`scripts/report-skips.sh` names `scripts/expected-skips/ci.txt` instead
of carrying *"15 skips when green"* — a figure whose own qualifier was
the false part, taken from a red, incomplete run (**D179**) — and
`herd-runner/src/cgroup.rs` names that list instead of *"the thirteen
standing skips"*.
